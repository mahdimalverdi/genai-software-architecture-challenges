## مسئله‌ی اصلی

این منبع مسئله‌ی تزریق دستور به مدل زبانی را به‌صورت یک مسئله‌ی امنیتی قابل‌تعریف و قابل‌آزمون صورت‌بندی می‌کند. در سامانه‌های مبتنی بر مدل زبانی، ورودی کاربر، داده‌ی بازیابی‌شده، خروجی ابزارها و دستورهای سیستمی در یک فضای متنی مشترک به مدل داده می‌شوند. همین هم‌نشینی باعث می‌شود مرز میان «دستور معتبر» و «داده‌ی غیرقابل‌اعتماد» از نظر مدل روشن نباشد.

## پیام محوری

پیام اصلی مقاله این است که تزریق دستور فقط یک ضعف در prompt نویسی نیست؛ یک مسئله‌ی معماری در کنترل مرز اعتماد، ترکیب context و اجرای عملیات بر اساس خروجی مدل است. هر معماری‌ای که داده‌ی بیرونی را وارد prompt کند و سپس بر اساس پاسخ مدل اقدام اجرایی انجام دهد، باید prompt injection را به‌عنوان تهدید طراحی در نظر بگیرد.

## ارتباط با معماری نرم‌افزار

این مقاله برای گزارش معماری مهم است چون نشان می‌دهد در سامانه‌های GenAI، لایه‌ی prompt و context به بخشی از سطح حمله تبدیل می‌شود. بنابراین طراحی معماری باید میان داده، دستور، سیاست اجرایی و مجوز ابزارها تفکیک صریح ایجاد کند. این تفکیک باید در سطح pipeline، orchestration، retrieval، tool calling و logging دیده شود.

## معیارها و شاخص‌های ارزیابی

- معیار: نرخ موفقیت حمله
- کاربرد: سنجش اینکه prompt injection تا چه حد می‌تواند هدف مهاجم را محقق کند
- محدودیت: وابسته به سناریو و تعریف موفقیت حمله است

- معیار: نرخ حفظ رفتار مطلوب پس از اعمال دفاع
- کاربرد: بررسی trade-off میان امنیت و کیفیت پاسخ
- محدودیت: ممکن است دفاع، پاسخ‌های سالم را هم بیش از حد محدود کند

## کیفیت و محدودیت منبع

- نوع شواهد: صورت‌بندی نظری همراه با benchmark و آزمایش امنیتی
- قوت اصلی: تبدیل prompt injection از مشاهده‌ی پراکنده به مسئله‌ای قابل‌تعریف و قابل‌آزمون
- ضعف اصلی: تمرکز آن بیشتر روی سطح prompt و benchmark است و همه‌ی پیامدهای معماری سازمانی را پوشش نمی‌دهد
- میزان اتکا در گزارش: بالا برای بخش امنیت، مرز اعتماد و معماری context

## جایگاه در گزارش نهایی

- استفاده در بخش «چالش‌های امنیتی GenAI»
- استفاده در تحلیل «Prompt به‌عنوان سطح حمله»
- پشتیبانی از این ادعا که معماری RAG و Agent باید سیاست صریح برای داده‌ی غیرقابل‌اعتماد داشته باشد

## نکته‌های قابل نقل یا استفاده

- تزریق دستور یک مسئله‌ی صرفاً زبانی نیست؛ نتیجه‌ی نبود جداسازی معماری میان دستور و داده است.
- هر داده‌ای که وارد context می‌شود، باید از نظر اعتماد، مالکیت و مجوز استفاده برچسب‌گذاری شود.

## جمع‌بندی نهایی برای این منبع

این مقاله برای گزارش نهایی منبعی کلیدی در توضیح ریسک امنیتی GenAI است. ارزش اصلی آن در این است که prompt injection را به‌عنوان مسئله‌ای قابل‌صورت‌بندی و قابل‌ارزیابی معرفی می‌کند. از منظر معماری نرم‌افزار، نتیجه‌ی مهم این است که طراحی امن سامانه‌های GenAI باید فراتر از prompt engineering باشد و شامل جداسازی trust boundary، کنترل context، محدودسازی ابزارها و ارزیابی امنیتی مستمر شود.
