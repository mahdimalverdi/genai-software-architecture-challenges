## مسئله‌ی اصلی
این منبع نشان می‌دهد که برنامه‌های متصل به مدل زبانی، فقط از ورودی مستقیم کاربر آسیب‌پذیر نمی‌شوند. اگر برنامه از محتوای بیرونی مانند صفحه‌ی وب، ایمیل، سند، مخزن کد یا ابزارهای متصل استفاده کند، مهاجم می‌تواند دستور مخرب را در همان منبع بیرونی پنهان کند و مدل را وادار کند برخلاف هدف اصلی سیستم عمل کند.

## پیام محوری
در برنامه‌های LLM-integrated، مرز اعتماد فقط میان «کاربر» و «سیستم» نیست. هر داده‌ی خارجی که وارد context مدل می‌شود می‌تواند به کانال دستور تبدیل شود. بنابراین معماری باید میان داده و دستور تمایز عملیاتی ایجاد کند و ورودی‌های بازیابی‌شده یا ابزارمحور را غیرقابل اعتماد فرض کند.

## ارتباط با معماری نرم‌افزار
این مقاله برای گزارش معماری مهم است چون prompt injection را از سطح prompt engineering به سطح threat model و طراحی boundary منتقل می‌کند. در معماری RAG، عامل‌های متصل به ابزار، مرورگرهای هوشمند، ایمیل‌خوان‌ها و دستیارهای سازمانی، context از منابع بیرونی می‌آید و همان context می‌تواند رفتار سیستم را تغییر دهد.

- ضعف اصلی: دفاع‌های کامل و استانداردشده ارائه نمی‌کند و بیشتر روی تهدید تمرکز دارد

## نکته‌های قابل نقل یا استفاده

- هر داده‌ی بیرونی که وارد context مدل شود، می‌تواند به یک بردار حمله تبدیل شود.
- اتصال مدل به ابزار، prompt injection را از خطای متنی به ریسک عملیاتی تبدیل می‌کند.

## جمع‌بندی نهایی برای این منبع

این منبع برای گزارش نشان می‌دهد معماری سامانه‌های GenAI باید امنیت context را جدی بگیرد. مسئله فقط تولید پاسخ اشتباه نیست؛ وقتی مدل به ابزار، داده‌ی خصوصی یا عملیات واقعی وصل است، context آلوده می‌تواند باعث نقض امنیت، افشای داده یا اجرای عملیات ناخواسته شود.
