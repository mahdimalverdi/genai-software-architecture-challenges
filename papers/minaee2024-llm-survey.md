## مسئله‌ی اصلی
این منبع نمایی جامع از مدل‌های زبانی بزرگ، روند تکامل آن‌ها، معماری‌های پایه، داده و آموزش، تنظیم با دستور، ارزیابی، کاربردها و چالش‌های باز ارائه می‌کند. مسئله‌ی اصلی برای گزارش این است که LLM یک قابلیت منفرد نیست، بلکه اکوسیستمی از مدل، داده، زیرساخت، ارزیابی، امنیت و محصول است.

## پیام محوری
LLMها به‌دلیل توانایی تولید، استدلال زبانی، خلاصه‌سازی، کدنویسی و تعامل با ابزارها، به زیرساختی عمومی برای سامانه‌های نرم‌افزاری جدید تبدیل شده‌اند؛ اما استفاده‌ی عملی از آن‌ها بدون مدیریت هزینه، تأخیر، امنیت، کیفیت و ارزیابی قابل اتکا نیست.

## ارتباط با معماری نرم‌افزار
این مقاله برای گزارش نقش زمینه‌ای دارد. در معماری نرم‌افزار، شناخت قابلیت‌ها و محدودیت‌های LLM کمک می‌کند تصمیم بگیریم کدام بخش سامانه باید مدل‌محور باشد، کجا باید retrieval یا ابزار اضافه شود، کجا باید خروجی کنترل شود و کجا استفاده از مدل از نظر هزینه یا ریسک مناسب نیست.

## معیارها و شاخص‌های ارزیابی

- معیار: accuracy، factuality، reasoning ability، robustness، latency، cost، safety
- کاربرد: مقایسه‌ی مدل‌ها، انتخاب مدل مناسب برای کارکردهای مختلف و سنجش کیفیت سیستم.
- محدودیت: benchmarkهای عمومی همیشه با دامنه‌ی واقعی محصول هم‌راستا نیستند.

## کیفیت و محدودیت منبع

- نوع شواهد: survey گسترده
- قوت اصلی: پوشش جامع اکوسیستم LLM و ایجاد زمینه‌ی مفهومی برای گزارش
- ضعف اصلی: برای تصمیم‌های عمیق معماری production به منابع تخصصی‌تر سروینگ، RAGOps و امنیت نیاز دارد.
- میزان اتکا در گزارش: متوسط تا زیاد، به‌عنوان منبع زمینه‌ای و چارچوب کلی

## جایگاه در گزارش نهایی

- مقدمه‌ی فنی درباره‌ی LLMها
- بخش چرخه‌ی عمر سامانه‌های GenAI
- بخش ویژگی‌های کیفی اثرپذیر از مدل
- بخش تصمیم‌های کلان معماری درباره‌ی انتخاب مدل، ارزیابی و استقرار

## نکته‌های قابل نقل یا استفاده

- LLMها باید به‌عنوان سرویس‌های غیرقطعی و پرهزینه در معماری دیده شوند.
- انتخاب مدل، prompt، داده و ارزیابی همگی تصمیم معماری‌اند.
- یک معماری پایدار باید نسبت به تغییر سریع مدل‌ها مقاوم باشد.

## جمع‌بندی نهایی برای این منبع

این منبع تصویر کلی و قابل اتکایی از فضای LLM ارائه می‌کند و برای گزارش به‌عنوان پایه‌ی مفهومی مناسب است. کاربرد اصلی آن این است که نشان دهد معماری GenAI فقط اضافه‌کردن API مدل نیست؛ بلکه شامل تصمیم‌های مرتبط با داده، ارزیابی، سروینگ، امنیت، هزینه و تجربه‌ی کاربر است.
