## مسئله‌ی اصلی
این منبع به مهندسی کاربردهای مبتنی بر مدل‌های بنیادین می‌پردازد. مسئله‌ی اصلی آن است که ساخت محصول با مدل‌های زبانی و مدل‌های بنیادین فقط به انتخاب یک مدل یا نوشتن prompt محدود نیست. محصول واقعی به طراحی داده، prompt، retrieval، ارزیابی، fine-tuning، caching، latency management، safety، monitoring و تجربه‌ی کاربر وابسته است.

در چنین سامانه‌هایی مدل معمولاً یک سرویس احتمالاتی و غیرقطعی است. بنابراین مهندسی نرم‌افزار باید با عدم قطعیت خروجی، تغییر نسخه‌ی مدل، هزینه‌ی inference، کیفیت داده‌ی زمینه‌ای و ریسک hallucination کنار بیاید.

## پیام محوری
پیام محوری منبع این است که کاربردهای AI باید مثل سامانه‌های مهندسی‌شده طراحی شوند، نه مثل demoهای promptمحور. برای رسیدن به محصول قابل اتکا باید evaluation، observability، data pipeline، model selection و iteration loop از ابتدا در معماری دیده شوند.

## ارتباط با معماری نرم‌افزار
این منبع برای گزارش نهایی مهم است، چون bridge بین مهندسی محصول و معماری GenAI ایجاد می‌کند. مفاهیمی مثل prompt engineering، RAG، evaluation، latency/cost trade-off، agentic workflows و monitoring را به تصمیم‌های معماری پیوند می‌دهد.

در گزارش می‌توان از این منبع برای توضیح این نکته استفاده کرد که معماری GenAI باید از ابتدا برای تغییرپذیری مدل، عدم قطعیت خروجی و ارزیابی مداوم طراحی شود.

## معیارها و شاخص‌های ارزیابی

- معیار: task success rate
- کاربرد: سنجش موفقیت واقعی application در سناریوهای کاربر
- محدودیت: تعریف success برای کارهای باز دشوار است

- معیار: latency و cost per request
- کاربرد: تصمیم‌گیری بین مدل‌های بزرگ، کوچک، cache و batching
- محدودیت: کاهش هزینه ممکن است کیفیت را کاهش دهد

- معیار: hallucination/error rate
- کاربرد: پایش خروجی‌های غلط یا بی‌پایه
- محدودیت: نیازمند ground truth یا evaluator معتبر است

- معیار: user feedback و escalation rate
- کاربرد: سنجش کیفیت در محیط واقعی
- محدودیت: feedback کاربران noisy و جهت‌دار است

## کیفیت و محدودیت منبع

- نوع شواهد: کتاب کاربردی و مهندسی
- قوت اصلی: اتصال مفاهیم GenAI به تصمیم‌های واقعی محصول و معماری
- ضعف اصلی: نسبت به مقالات پژوهشی، شواهد تجربی کنترل‌شده‌ی کمتری ارائه می‌کند
- میزان اتکا در گزارش: بالا برای بخش طراحی کاربردهای GenAI و trade-offهای محصولی

## جایگاه در گزارش نهایی

- بخش معماری کاربردهای مبتنی بر مدل‌های بنیادین
- بخش evaluation و iteration loop
- بخش trade-off میان کیفیت، latency و هزینه
- بخش RAG، prompt و observability در محصول واقعی

## نکته‌های قابل نقل یا استفاده

- محصول GenAI فقط یک prompt نیست؛ یک سامانه‌ی کامل با داده، ارزیابی، زیرساخت و عملیات است.
- evaluation باید بخشی از چرخه‌ی توسعه باشد، نه مرحله‌ای بعد از ساخت محصول.
- انتخاب مدل، کیفیت داده و تجربه‌ی کاربر باید هم‌زمان در معماری دیده شوند.
