## مسئله‌ی اصلی

این مقاله مسئله‌ی ارزیابی خودکار سامانه‌های RAG را بررسی می‌کند. مشکل اصلی این است که ارزیابی RAG فقط با سنجش پاسخ نهایی کافی نیست، چون ممکن است پاسخ بد به‌دلیل بازیابی ضعیف، context نامناسب یا تولید نادرست مدل ایجاد شده باشد. RAGAs تلاش می‌کند معیارهایی بدهد که هم کیفیت بازیابی و هم کیفیت تولید پاسخ را جداگانه بررسی کنند.

## پیام محوری

پیام اصلی مقاله این است که RAG برای تولید قابل اتکا باید با معیارهای چندبخشی ارزیابی شود. ارزیابی باید نشان دهد آیا context بازیابی‌شده مرتبط بوده، آیا پاسخ به context وفادار مانده، و آیا پاسخ واقعاً پرسش کاربر را پوشش داده است.

## ارتباط با معماری نرم‌افزار

این منبع برای معماری مهم است چون ارزیابی را به یک component مستقل در معماری RAG تبدیل می‌کند. در سامانه‌ی GenAI، evaluator فقط ابزار آزمایش نیست؛ بخشی از چرخه‌ی عملیات، regression testing، monitoring و کنترل کیفیت است. بنابراین معماری باید امکان ثبت پرسش، context، پاسخ، ground truth و نتیجه‌ی ارزیابی را فراهم کند.

## معیارها و شاخص‌های ارزیابی

- معیار: faithfulness
- کاربرد: سنجش اینکه پاسخ واقعاً از context پشتیبانی می‌شود یا نه
- محدودیت: داوری خودکار ممکن است خودش خطا داشته باشد

- معیار: answer relevancy
- کاربرد: سنجش ارتباط پاسخ با پرسش کاربر
- محدودیت: ممکن است پاسخ مرتبط ولی ناقص باشد

- معیار: context precision و context recall
- کاربرد: ارزیابی کیفیت بازیابی و context ورودی مدل
- محدودیت: برای برخی دامنه‌ها نیاز به ground truth یا داده‌ی مرجع دارد

## کیفیت و محدودیت منبع

- نوع شواهد: ابزارمحور / تجربی / نمایشی
- قوت اصلی: ارائه‌ی معیارهای عملی برای تفکیک خطاهای RAG
- ضعف اصلی: اتکا به داوری خودکار و LLM-as-judge می‌تواند خطای ارزیابی ایجاد کند
- میزان اتکا در گزارش: زیاد

## جایگاه در گزارش نهایی

این منبع در بخش‌های زیر استفاده می‌شود:

- معماری نمونه‌ی RAG
- ارزیابی و آزمون‌پذیری
- مشاهده‌پذیری و عملیات
- اعتمادپذیری و کنترل کیفیت

## نکته‌های قابل نقل یا استفاده

- ارزیابی RAG باید هم retrieval و هم generation را جداگانه بسنجد.
- faithfulness معیار کلیدی برای تشخیص پاسخ‌های ظاهراً درست اما بی‌پشتوانه است.
- evaluator می‌تواند بخشی از معماری runtime و regression testing باشد.

## جمع‌بندی نهایی برای این منبع

این مقاله یکی از منابع اصلی بخش ارزیابی است. ارزش آن در تبدیل ارزیابی RAG به مجموعه‌ای از معیارهای قابل استفاده در pipeline و عملیات تولیدی است. در گزارش باید از آن برای نشان‌دادن ضرورت لایه‌ی evaluation و تفکیک خطاهای بازیابی از تولید استفاده شود.
