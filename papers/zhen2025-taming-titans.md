## مسئله‌ی اصلی

این منبع مسئله‌ی سرویس‌دهی کارآمد مدل‌های زبانی بزرگ را بررسی می‌کند. نقطه‌ی شروع مقاله این است که کیفیت مدل تنها بخش کوچکی از مسئله‌ی ساخت سرویس‌های GenAI است؛ در محیط عملیاتی، هزینه‌ی GPU، محدودیت حافظه، تأخیر پاسخ، throughput، batching، زمان‌بندی درخواست‌ها و مدیریت cache به اندازه‌ی خود مدل تعیین‌کننده می‌شوند. بنابراین مسئله‌ی اصلی مقاله، تبدیل اجرای مدل زبانی از یک فعالیت آزمایشگاهی به یک زیرساخت production-grade برای inference است.

## پیام محوری

پیام اصلی منبع این است که inference serving برای LLMها یک مسئله‌ی معماری مستقل است، نه فقط یک مسئله‌ی بهینه‌سازی کد. در سرویس‌های واقعی، تصمیم‌هایی مانند انتخاب parallelism، مدیریت KV cache، batching پیوسته، جداسازی prefill و decode، quantization و سیاست زمان‌بندی، مستقیماً کیفیت‌های معماری مانند کارایی، مقیاس‌پذیری، هزینه و قابلیت اطمینان را تعیین می‌کنند.

## ارتباط با معماری نرم‌افزار

این منبع برای پروژه مهم است چون نشان می‌دهد سامانه‌های مبتنی بر LLM در لایه‌ی serving با سرویس‌های نرم‌افزاری معمولی تفاوت جدی دارند. در این سامانه‌ها، latency فقط نتیجه‌ی کندی شبکه یا دیتابیس نیست؛ بلکه از ویژگی autoregressive تولید متن، طول prompt، طول خروجی، حافظه‌ی KV cache، ظرفیت GPU و سیاست batching ناشی می‌شود. بنابراین معماری باید بین هزینه، سرعت پاسخ، کیفیت خروجی و ظرفیت سرویس‌دهی موازنه برقرار کند.

## معیارها و شاخص‌های ارزیابی

- معیار: latency
- کاربرد: سنجش تجربه‌ی کاربر و سرعت پاسخ سامانه
- محدودیت: به طول prompt، طول خروجی و بار سیستم وابسته است

- معیار: throughput
- کاربرد: سنجش ظرفیت سرویس‌دهی در تعداد درخواست یا token بر ثانیه
- محدودیت: بدون توجه به latency ممکن است گمراه‌کننده باشد

- معیار: GPU utilization و memory footprint
- کاربرد: سنجش بهره‌وری زیرساخت و هزینه
- محدودیت: باید همراه با کیفیت خروجی و پایداری بررسی شود

## نکته‌های قابل نقل یا استفاده

- در سرویس‌های LLM، inference serving خودش یک لایه‌ی معماری مستقل است.
- محدودیت حافظه و KV cache می‌تواند به اندازه‌ی وزن مدل روی ظرفیت سامانه اثر بگذارد.
- بهینه‌سازی serving همیشه یک trade-off میان هزینه، latency، throughput و کیفیت خروجی است.

## جمع‌بندی نهایی برای این منبع

این منبع برای گزارش وزن زیادی دارد، چون بخش مهمی از چالش‌های معماری GenAI را از زاویه‌ی عملیاتی و زیرساختی توضیح می‌دهد. مقاله کمک می‌کند نشان دهیم معماری سامانه‌ی LLM فقط prompt، RAG یا مدل نیست؛ بلکه serving layer و تصمیم‌های runtime نیز بخش اصلی معماری هستند.
