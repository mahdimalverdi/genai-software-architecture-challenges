## مسئله‌ی اصلی

این مقاله مسئله‌ی حمله‌ی prompt injection غیرمستقیم را در برنامه‌های LLM بررسی می‌کند؛ یعنی وضعیتی که دستور مخرب نه از طرف کاربر، بلکه از محتوای خارجی وارد context مدل می‌شود. این مسئله برای معماری سرویس‌های RAG، agent و ابزارهای متصل به وب مهم است، چون سیستم ناچار است داده‌ی بیرونی را وارد prompt کند. مقاله با معرفی benchmark به نام BIPIA نشان می‌دهد که مدل‌ها در تمایز میان «اطلاعات برای خواندن» و «دستور برای اجرا» ضعف دارند.

## پیام محوری

پیام محوری مقاله این است که هر سرویس LLM که محتوای خارجی را وارد context کند، در معرض prompt injection غیرمستقیم است. بنابراین امنیت چنین سامانه‌ای فقط با کنترل ورودی کاربر تأمین نمی‌شود؛ باید مرز میان دستور سیستم، درخواست کاربر و محتوای بیرونی در معماری و prompt design صریح شود.

## ارتباط با معماری نرم‌افزار

این منبع برای معماری نرم‌افزار مهم است چون نشان می‌دهد امنیت LLM application به مرزبندی معماری میان اجزای سیستم وابسته است. در معماری‌های RAG و agent، retrieval layer، tool layer، prompt assembly و policy layer باید طوری طراحی شوند که محتوای خارجی نتواند نقش دستور اجرایی بگیرد. مقاله همچنین نشان می‌دهد که security evaluation باید بخشی از چرخه‌ی آزمون و عملیات باشد.

## معیارها و شاخص‌های ارزیابی

- معیار: attack success rate
- کاربرد: سنجش میزان موفقیت prompt injection
- محدودیت: به تعریف سناریو و مدل حمله وابسته است

- معیار: کیفیت خروجی پس از دفاع
- کاربرد: بررسی اینکه دفاع امنیتی کارکرد اصلی برنامه را خراب نکرده باشد
- محدودیت: سنجش کیفیت خروجی LLM همیشه وابسته به داوری یا متریک کمکی است
