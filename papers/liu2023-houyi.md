## مسئله‌ی اصلی
برنامه‌های متصل به LLM اغلب ورودی کاربر، prompt سیستمی، ابزارها و داده‌های خارجی را در یک زمینه واحد ترکیب می‌کنند. همین ترکیب باعث می‌شود مدل نتواند همیشه مرز میان دستور معتبر برنامه و متن تزریق‌شده توسط مهاجم را تشخیص دهد. مقاله نشان می‌دهد که prompt injection فقط یک مسئله prompt نویسی نیست، بلکه یک ریسک معماری برای کل برنامه‌های LLM-integrated است.

## پیام محوری
HouYi نشان می‌دهد که حملات prompt injection در برنامه‌های واقعی قابل اجرا هستند و می‌توانند به پیامدهایی مثل prompt theft، سوءاستفاده از قابلیت‌های برنامه و دور زدن سیاست‌های intended behavior منجر شوند. بنابراین امنیت LLM باید در سطح معماری برنامه، مرزبندی trust، کنترل ابزارها و طراحی ورودی/خروجی دیده شود.

## ارتباط با معماری نرم‌افزار
این مقاله برای بخش «ریسک‌های امنیتی معماری GenAI» مهم است. در معماری سنتی، ورودی کاربر معمولاً داده تلقی می‌شود؛ اما در برنامه‌های LLM، داده می‌تواند به دستور تبدیل شود. بنابراین لایه‌های prompt construction، retrieval، tool execution، session context و output handling باید به‌عنوان سطوح حمله بررسی شوند.

## معیارها و شاخص‌های ارزیابی

- معیار: نرخ موفقیت حمله، تعداد برنامه‌های آسیب‌پذیر، نوع پیامد حمله، شدت اثر روی دارایی‌ها
- کاربرد: ارزیابی امنیتی برنامه‌های LLM-integrated پیش از انتشار و پس از تغییر prompt/model
- محدودیت: نتایج به نوع برنامه، سطح دسترسی ابزارها، prompt داخلی و سیاست‌های محصول وابسته است.

## کیفیت و محدودیت منبع

- نوع شواهد: تحلیل امنیتی و آزمایش روی برنامه‌های واقعی
- قوت اصلی: انتقال بحث prompt injection از مثال‌های ساده به سطح برنامه‌های واقعی
- ضعف اصلی: دفاع‌ها به‌صورت کامل و سیستماتیک حل نمی‌شوند و بیشتر ریسک و امکان حمله برجسته می‌شود.
- میزان اتکا در گزارش: بالا برای بخش امنیت، threat model و معماری اعتماد

## جایگاه در گزارش نهایی

- قابل استفاده در بخش امنیت و threat modeling سامانه‌های GenAI
- مناسب برای توضیح چرایی نیاز به guardrail خارج از مدل
- قابل استفاده در بحث «ورودی کاربر در LLM هم داده است و هم بالقوه دستور»

## نکته‌های قابل نقل یا استفاده

- prompt injection در برنامه‌های واقعی صرفاً یک سناریوی نظری نیست.
- محرمانه نگه‌داشتن prompt به‌تنهایی یک کنترل امنیتی کافی نیست.
- ابزارها و actionهای متصل به LLM باید با policy مستقل محدود شوند.

## جمع‌بندی نهایی برای این منبع

HouYi یکی از منابع مهم برای نشان دادن ریسک امنیتی برنامه‌های LLM-integrated است. پیام معماری آن روشن است: وقتی مدل در مرکز تصمیم‌گیری، retrieval و tool execution قرار می‌گیرد، prompt injection به یک مسئله مرزبندی trust و کنترل action تبدیل می‌شود، نه فقط یک مشکل متن prompt.
