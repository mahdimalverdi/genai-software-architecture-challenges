## مسئله‌ی اصلی
این منبع مسئله‌ی سرویس‌دهی استنتاج مدل‌های زبانی بزرگ را بررسی می‌کند؛ یعنی اینکه چگونه یک مدل بزرگ در محیط واقعی با محدودیت حافظه، تأخیر، توان عملیاتی، هزینه و تغییرپذیری درخواست‌ها به‌صورت پایدار اجرا شود. مسئله فقط اجرای مدل نیست؛ بلکه مدیریت صف، batch کردن، زمان‌بندی، حافظه‌ی KV cache، توزیع بار و استفاده‌ی بهینه از GPU در مقیاس سرویس است.

## پیام محوری
استنتاج LLM یک workload تعاملی و stateful است. معماری سرویس‌دهی باید هم مرحله‌ی prefill و هم مرحله‌ی decode را مدیریت کند، زیرا این دو مرحله نیازهای محاسباتی و حافظه‌ای متفاوتی دارند. بهینه‌سازی فقط در سطح مدل کافی نیست و باید در سطح runtime، scheduler، memory manager و serving platform انجام شود.

## ارتباط با معماری نرم‌افزار
این مقاله برای گزارش معماری مهم است، چون نشان می‌دهد سرویس GenAI از دید معماری شبیه یک API ساده نیست. پشت endpoint تولید متن، یک زیرسیستم پیچیده‌ی inference serving قرار دارد که مستقیماً روی کارایی، مقیاس‌پذیری، هزینه، پایداری و تجربه‌ی کاربر اثر می‌گذارد.

## معیارها و شاخص‌های ارزیابی

- معیار: latency و tail latency
- کاربرد: سنجش تجربه‌ی کاربر در سرویس تعاملی
- محدودیت: میانگین latency برای تحلیل کیفیت سرویس کافی نیست

- معیار: throughput / tokens per second
- کاربرد: سنجش بهره‌وری زیرساخت
- محدودیت: ممکن است با افزایش throughput، تأخیر کاربر بدتر شود

- معیار: GPU utilization و memory utilization
- کاربرد: ظرفیت‌سنجی و کنترل هزینه
- محدودیت: استفاده‌ی بالا از GPU همیشه به معنای SLA بهتر نیست

## کیفیت و محدودیت منبع

- نوع شواهد: مرور فنی پیشرفت‌ها و فرصت‌های سرویس‌دهی LLM
- قوت اصلی: اتصال روشن بین ویژگی‌های LLM و تصمیم‌های معماری runtime
- ضعف اصلی: تمرکز مقاله بیشتر روی زیرساخت inference است و کمتر وارد لایه‌های محصول، امنیت یا governance می‌شود
- میزان اتکا در گزارش: بالا برای بخش معماری serving و هزینه‌ی عملیاتی GenAI

## جایگاه در گزارش نهایی

- بخش چالش‌های زیرساختی و عملیاتی GenAI
- بخش مقیاس‌پذیری و performance در سرویس‌های LLM
- بخش trade-off میان latency، throughput و cost

## نکته‌های قابل نقل یا استفاده

- serving مدل زبانی بزرگ باید به‌عنوان یک زیرسیستم معماری مستقل دیده شود، نه صرفاً یک فراخوانی مدل.
- بهینه‌سازی inference ترکیبی از runtime، scheduler، memory management و عملیات زیرساخت است.

## جمع‌بندی نهایی برای این منبع

این منبع نشان می‌دهد که در معماری سرویس‌های GenAI، بخش inference serving یکی از نقاط اصلی ریسک و هزینه است. تصمیم‌هایی مانند batching، scheduling، مدیریت حافظه و تفکیک prefill/decode مستقیماً روی SLA، هزینه و مقیاس‌پذیری اثر می‌گذارند و باید در گزارش نهایی به‌عنوان چالش معماری مستقل بررسی شوند.
